# opencode-free-router

A local router that lets **OpenCode** (and any OpenAI-compatible coding agent) keep working on **free-tier LLM quotas**: it measures the providers, sends big agent requests only to fast ones, switches automatically on quota errors, and fails fast with a clear message instead of hanging.

> Built by **Oscar Mulume** — [M-SEC Technology Consulting](https://oscarmulume.github.io/msec-technology-consulting/) · [Portfolio](https://oscarmulume.github.io/)
> Français : [docs/README.fr.md](docs/README.fr.md)

## The problem

Coding agents send large prompts (20–30K tokens) many times. Free tiers cap requests per minute or per day, some refuse big prompts (HTTP 413/429), and a local CPU model can take minutes per answer. The result: the agent stalls for minutes, or silently falls back to something unusably slow.

## How it works

```text
OpenCode / Aider / Continue / Hermes / any OpenAI client
                    |
                    v
        LiteLLM proxy, local (127.0.0.1:4000)
                    |
   +----------------+-----------------------------+
   | free-auto      big agent requests: only providers MEASURED < 30 s to first token on 30K tokens,
   |                fastest first, local model EXCLUDED
   | free-fast      small requests (< 6K tokens): fastest first, local Ollama as last resort
   | free-check     same rules as free-auto, reverse order (a second model reviews the first)
   | free-exhausted instant, explicit answer when every fast provider is out of quota
   +----------------+-----------------------------+
        providers: Gemini · Groq · GitHub Models · Cloudflare Workers AI · NVIDIA NIM · Ollama
```

- **Bench** (`scripts/bench.py`): measures each configured provider live: availability, time to first token and throughput for a 1K and a 30K-token request, real context ceiling, 413/429 errors. Output: `bench.json` in the data folder.
- **Routing**: the groups above are *generated* from the bench (`scripts/render-config.py`). A provider that is slow or exhausted is not in the big-request group.
- **Cooldown**: after a failure a provider is paused (LiteLLM `allowed_fails` / `cooldown_time`), then retried.
- **Self-tuning**: every 2 hours a short bench re-runs; slow or exhausted providers are disabled and re-enabled when they get fast again (`scripts/autoreglage.py`). `scripts/status.ps1` prints OK / SLOW / EXHAUSTED / NO KEY with the measured delay.
- **Fail fast**: if all fast providers are exhausted, the answer is an immediate message (not a 30-minute wait) so the agent can stop cleanly.
- **Two-model reviewer**: `free-check` uses a different provider order, so a different model can review the work of `free-auto`.

## Install (Windows, PowerShell)

```powershell
git clone https://github.com/OscarMulume/opencode-free-router; cd opencode-free-router
setx GEMINI_API_KEY "<your key>"        # and/or GROQ_API_KEY ... (see the provider table), then reopen the terminal
.\scripts\installer.ps1                 # venv, LiteLLM, local key, scheduled task, health check
```

Then point your tool at `http://localhost:4000/v1` with the local key `LITELLM_MASTER_KEY` (generated by the installer, never printed). Ready-made files for OpenCode, Hermes Agent, Aider, Continue and plain OpenAI clients are in [`integrations/`](integrations) and explained in [`docs/INTEGRATIONS.md`](docs/INTEGRATIONS.md).

Daily use: `scripts\status.ps1` (what is up, what the last requests used), `scripts\bench.ps1` (full bench; `-Court` for the short one).

## Providers

`scripts/providers.yaml` is the registry. **A provider is active only if its environment variable exists.** Model names change often: check each provider's official documentation; the bench keeps only models that the provider's `/models` endpoint announces.

| Provider | Variable(s) | Notes |
|---|---|---|
| Google Gemini (Flash, Flash-Lite) | `GEMINI_API_KEY` | free tier, no card |
| Groq | `GROQ_API_KEY` | free tier, no card; refuses prompts above ~8K tokens/min |
| GitHub Models | `GITHUB_MODELS_TOKEN` | dedicated fine-grained token with `models: read`; never reuse your git token |
| Cloudflare Workers AI | `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` | free daily allowance |
| NVIDIA NIM | `NVIDIA_API_KEY` | trial offer; kept disabled while the bench measures it slow |
| Ollama (local) | none | last resort for small requests only |
| Cerebras, OpenRouter (`:free`), Mistral | `CEREBRAS_API_KEY`, `OPENROUTER_API_KEY`, `MISTRAL_API_KEY` | **disabled in this repository: sign-up requires a bank card** (`necessite_carte: true`). Paid providers with a small free quota can be added the same way and are active only if you set their key. |

**Rule:** one account per provider, and respect each provider's terms of use. This project must not be used to create multiple accounts to get around a limit.

## Honest limits

- Free tiers come with **no guarantee**: quotas, models and terms change, and a provider can be saturated at any time. The router reduces stalls; it cannot create capacity.
- With a single fast provider (for example only Gemini Flash-Lite), a burst of 30K-token requests can still exhaust it; the router then answers with the explicit "quotas exhausted" message.
- A local model on a CPU-only PC is slow (a 7B model took about 9 minutes for 30K tokens on an i5-13400): it is a last resort for small requests, never used for big agent requests.
- Windows-first (PowerShell scripts and a scheduled task). The Python parts are portable; a Linux/macOS installer is on the [roadmap](https://github.com/users/OscarMulume/projects). Script messages are currently in French.
